# Шаблон отчёта аудита (два слоя)

Слой 1 наружу пользователю: только вердикт, препятствия и расхождения, ничего подтверждённого. Без кодов, номеров критериев, путей к файлам и слов «атом», «шапка воздействий», «manifest»: критерий называется текстом из каталога; D3 и D4 пишутся вместе с расшифровкой: D3 «зафиксировать выбор решения», D4 «позвать команду, документ готов к PRD». Не больше 25 строк.

```markdown
## Проверка: {название документа}

**Что проверяли:** можно ли принять решение «{переход словами}» ({D3 | D4}). {Если шапки нет: «В документе решение не заявлено, взяли {D-код} по содержимому: {что нашли}».} {Если флаг поднят: «Документ уже содержит артефакты следующего шага: {что именно}».}
**Вердикт:** {Достаточно, можно принимать решение | Недостаточно: {N} препятствий}
**Почему:** {одна фраза: главное препятствие или главная опора}

### Чего не хватает (показано {n}, ещё {m} в машинном слое)
1. **{Что не так, по содержанию, а не имя причины}**
   Где: «{дословная цитата}», {раздел}. {Если нет: «в документе не нашли, искали в {раздел}»}
   Что сделать: {действие из reason-action-map.md, конкретизированное}. Кто: {автор | аналитик | {сторона}}.
   Готово, когда: {что должно появиться в документе}.
2. …
3. …
{Только если есть: «Также расходится: {противоречия между блоками; устаревшие замеры; утверждения только по ссылке}».}

### Что перевернуло бы вывод
{Самое дешёвое наблюдение против центрального утверждения}. В документе: {есть: цитата | нет}.

### Границы проверки
Прочитано: {список}. Не прочитано: {список или «ничего»}. Недоступно: {список или «ничего»}.
{Если шапки воздействий нет: «Условные проверки выключены: в шапке документа нет блока о том, что задеваем (деньги, юристы, чужие команды, поверхности, способ запуска). Вне препятствий: заполнить этот блок по шаблону скилла».}
Стадия: {New Idea | Opportunity Discovery | Solution Discovery | Ready for Dev}. По сравнению с прошлой проверкой: {закрыто N, появилось M | первая проверка}.
```

Правила: заголовок всегда с названием документа («## Проверка: {название}»); порядок препятствий фиксирован (невалидный объект → противоречие или устаревшее → критерии по номерам, при D4 сначала обязательные D3), максимум три, остальные считаются в «ещё {m}». При «Достаточно» блок «Чего не хватает» заменяется строкой «Препятствий нет»; улучшения не добавлять.

Слой 2, машинный: таблица «Результаты проверок». Если писать в документ можно, кладётся в секцию «Результаты проверок» документа; иначе в конец отчёта, обёрнутая в `<details><summary>Машинный слой</summary> … </details>`.

```
| Дата | Критерий | Статус (выполнен / не выполнен / неприменим / недоступен) | Цитата | Источник | Причина |
```

Правила: одна строка на критерий и на объект (вариант, сторону, риск); цитата дословная; «выполнен» без цитаты недействителен; «недоступен» только для существующего, но закрытого источника.

## Разбор по документу (по запросу)

Отдельное сообщение после отчёта, когда пользователь просит «разбор». Это рендер машинного слоя в порядке документа: каждая проверка привязана к разделу, где искали. Здесь показывается и пройденное, чтобы владелец увидел, какие части документа сработали, и мог не согласиться с конкретной проверкой.

```markdown
## Разбор: {название документа}

Как читать: иду по документу сверху вниз. ✅ проверка пройдена, ❌ не пройдена, ➖ не применялась к этому решению.

### {Раздел документа}
- ✅ {Что проверяли, словами из каталога}: «{цитата}» — {почему засчитано}.
- ❌ {Что проверяли}: «{цитата}» или «в разделе не нашли» — {чего именно не хватает}.
- ➖ {Что проверяли}: {почему не применялось}.

### Итого
- Применимых проверок: {M}; пройдено: {N}; не пройдено: {K}.
- Вердикт держится на: {1–3 непройденные проверки одной строкой}.
- Если не согласен с ❌ у «{проверка}»: покажи {что именно}, и она станет ✅.
```

Правила: та же дисциплина цитат; критерий называется словами, без ID и кодов; пройденные проверки показываются полностью, скрытых нет; счётчики здесь допустимы, проценты и баллы нет.
