# Purpose

Провести аудит сигнала и проблемы перед решением: взять сигнал в работу (D1), признать проблему подтверждённой и открыть поиск решений (D2) либо остановить или заморозить инициативу (D5).

# When to use

Пользователь просит проверить качество проработки сигнала или проблемы, обоснованность D1/D2 либо основания Stop/Park. Входом служит ссылка на страницу Confluence или путь к локальному файлу.

# When not to use

Не используй скилл для выбора или ревью решения (D3/D4): передай задачу в `$aipm-review-solution`. Готовый PRD передай в `prd-review`. Не используй для mandate, incident, compliance или research: v1 поддерживает только `track=discovery`.

# Required inputs

- ссылка на страницу Confluence или путь к локальному файлу;
- заявленный переход `D1`, `D2` или `D5` — в запросе либо в документе;
- `track=discovery` — в запросе либо в документе;
- ровно один decision thread, который можно решить независимо;
- supplied manifest: корневой документ считается явно переданным `IN_SCOPE`; дополнительные ресурсы включаются только с `resource_id`, locator и `scope_state`.

Если переход, трек или decision thread отсутствует, верни `BLOCKED` и задай один точный вопрос только о первом отсутствующем входе. Не угадывай его.

# Workflow

1. Прочитай [каталог критериев](assets/criteria-d1-d2-d5.md), [карту действий](assets/reason-action-map.md), [шаблон отчёта](assets/report-template.md) и [глоссарий](assets/glossary.md).
2. Открой корневой документ. Для ссылки Confluence используй `confluence-mcp`; для пути прочитай локальный файл. Не меняй источник без явной просьбы пользователя.
3. Выполни preflight: проверь locator, `transition`, `track`, один thread, supplied manifest и соответствие следующего commitment заявленному переходу.
4. Зафиксируй manifest и границы чтения. Не обходи ссылки рекурсивно и не добавляй найденные ссылки в scope. Непереданную ссылку зарегистрируй как недоступную зависимость.
5. Извлеки claims с устойчивыми ID, дословными цитатами, локациями и ссылками на evidence. Если гипотеза одна, считай её центральной; если их несколько, центральную обязан объявить автор.
6. Создай только экземпляры критериев заявленного перехода: безусловные CORE и закрыто-предикатные обязательные проверки из каталога. Для каждого заполни `applicability`, `assessability`, `result`, `primary_reason` и anchor. Не выдавай `MET` без дословной цитаты и локации; для доказательного claim дополнительно проверь источник.
7. Выполни проход-опровержение: назови самое дешёвое наблюдение, которое изменило бы вывод, и проверь, есть ли оно в supplied scope. Finding не меняет критерии или candidate без принятия владельцем.
8. Вычисли статус досье и candidate строго по каталогу. Честное evidence, которое опровергает гипотезу, может дать `MET`: проверяется верность связи и вывода, а не благоприятность результата.
9. Сформируй результат по шаблону: наружу человеческий слой без кодов (что проверяли, вердикт, почему, максимум три препятствия), затем машинный слой под свёрнутым блоком. Для каждого препятствия выбери одно минимальное действие по закрытой карте и запиши его фразой из глоссария.
10. Если изменение источника явно запрошено, добавь подтверждённые атомы с цитатами в append-only секцию аудита внутри документа. Иначе верни готовый для вставки блок и ничего не записывай.

# Constraints

- Используй только переходы D1, D2 и D5 и только рубрику v1 из assets.
- Результат атома: `APPLICABLE/NOT_APPLICABLE` → `ASSESSABLE/BLOCKED` → `MET/NOT_MET/null`. Не используй частичные баллы, веса, проценты готовности или рейтинг инициатив.
- Exposed candidate принимает только `D2_CANDIDATE`, `CONTINUE_CANDIDATE`, `STOP_CANDIDATE` или `BLOCKED`; дополнительно верни canonical candidate, `candidate_available` и `d5_mode: STOP | PARK | null`, чтобы не спутать Continue с отсутствием candidate.
- Все `MET` означают только decision-ready dossier для запрошенного перехода. Это не доказывает, что фича хорошая, проблема истинна, GO обязателен или будущее решение будет качественным.
- Внешняя опора обязательна для evidence-required claims. Фраза автора «подтверждено» доказательством не является.
- При сомнении между `MET` и `NOT_MET` выбирай `NOT_MET`. Конфликтующие источники не разрешай выбором удобного.
- Не предлагай косметическое «дописать раздел». Действие должно принести evidence, метод, границу, обязательный input, согласовать вывод, сузить/снять claim либо допустимо снизить commitment.
- Вердикт «достаточно для заявленного перехода» — штатный результат; при нём не придумывай улучшения.

# Definition of done

- все применимые CORE-атомы и закрыто-предикатные обязательные проверки заявленного перехода оценены с устойчивыми ID и anchors;
- все обязательные источники отражены в source coverage;
- выполнен проход-опровержение;
- первые строки отчёта — «Что проверяли», «Вердикт», «Почему» словами по глоссарию; статус досье, candidate, его доступность и режим D5 есть в машинном слое;
- показано не больше трёх расхождений, остальные учтены в `omitted_count`;
- подтверждённые атомы подготовлены для append-only audit section или записаны туда при явном разрешении.

# Output format

Используй [assets/report-template.md](assets/report-template.md). Сначала человеческий слой: без кодов статусов, действий и ID критериев, перевод по [assets/glossary.md](assets/glossary.md), не больше 25 строк. Затем машинный слой (YAML без изменений схемы) под `<details><summary>Машинный слой</summary>`. Append-only audit block не дублируй в человеческом feedback.

# Failure handling

Любой `BLOCKED` наружу выглядит как «Проверка не началась: {причина словами}» и ровно один вопрос с вариантами словами; код причины остаётся в машинном слое.

- Некорректный locator или manifest: `BLOCKED(INVALID_INPUT)` и один вопрос с точным требуемым значением.
- `track!=discovery`: `BLOCKED(TRACK_NOT_SUPPORTED)`; объясни границу v1, не оценивай содержание.
- Несколько независимых threads: `BLOCKED(INVALID_INPUT)` и попроси выбрать один thread.
- Несколько гипотез без центральной: `BLOCKED(CENTRAL_CLAIM_UNRESOLVED)` и попроси назвать `central_claim_id`.
- Обязательный источник не прочитан или недоступен: сохрани limitation и `BLOCKED(BLOCKED_SOURCE)`; не заменяй это `ABSENT`.
- Ссылка из документа вне supplied manifest: не открывай её; добавь synthetic dependency и укажи, какой criterion она блокирует.
- Ошибка чтения Confluence или файла: назови locator, причину и минимальное действие для восстановления доступа; не продолжай с частичным контекстом.
