# Карта primary reason → минимальное действие

Карта закрыта для rubric v1. Выбирай первый reason из порядка ниже, затем ровно одно primary action. Не заменяй действие советом «дописать раздел».

## Порядок primary reason

```text
INVALID_INPUT → TRACK_NOT_SUPPORTED → ABSENT → INVALID_FORM → TRANSITION_COMMITMENT_MISMATCH → CENTRAL_CLAIM_UNRESOLVED
→ SOURCE_REF_MISSING → BLOCKED_SOURCE → SOURCE_OBSERVATION_ABSENT → SOURCE_SCOPE_MISMATCH → SOURCE_PERIOD_MISMATCH
→ SOURCE_GRAIN_MISMATCH → SOURCE_VALUE_MISMATCH → CLAIM_TYPE_AMBIGUOUS → CLAIM_TYPE_UNSUPPORTED
→ METHOD_UNSPECIFIED → METHOD_NOT_ADMISSIBLE → METHOD_PROFILE_INCOMPLETE
→ DISCRIMINATION_RULE_MISSING → DISCRIMINATION_RULE_NON_OBSERVABLE
→ SELECTION_UNIVERSE_MISSING → SELECTION_RULE_MISSING → SCOPE_MISMATCH → UNSUPPORTED_GENERALIZATION
→ CONCLUSION_EVIDENCE_MISMATCH → ESSENTIAL_RELATION_MISSING → ESSENTIAL_RELATION_NOT_EVIDENCED
→ RIVAL_MODEL_MISSING → RIVAL_PREDICTION_MISSING → RIVAL_TEST_MISSING → RIVAL_RESULT_MISSING → RIVAL_STATUS_MISSING
→ UNCERTAINTY_DECISION_MAPPING_MISSING → UNCERTAINTY_NEXT_TEST_MISSING
→ EVIDENCE_DATE_MISSING → EVIDENCE_STALE → EVIDENCE_PRECEDES_MATERIAL_CHANGE
→ PROXY_TARGET_BRIDGE_MISSING → PROXY_OVERCLAIM → CIRCULAR_EVIDENCE → INDEPENDENT_VALIDATION_MISSING
→ CONFLICT_DISPOSITION_MISSING → CONCLUSION_CONFLICT_MISMATCH
```

## Закрытые actions

`PROVIDE_EVIDENCE | PROVIDE_METHOD | PROVIDE_BOUNDARY | PROVIDE_REQUIRED_INPUT | ALIGN_CONCLUSION | NARROW_CLAIM | WITHDRAW_CLAIM | LOWER_TRANSITION`

## Детерминированное отображение

Применяй правила сверху вниз; первое совпадение окончательное.

1. `DB-09 + TRANSITION_COMMITMENT_MISMATCH` → `LOWER_TRANSITION`: убрать implementation commitment и вернуть запрос к bounded Solution Discovery. Для D1/D5 lower route нет.
2. `CONCLUSION_EVIDENCE_MISMATCH` или `CONCLUSION_CONFLICT_MISMATCH` → `ALIGN_CONCLUSION`: привести авторский вывод к вычисленному evidence/conflict status, не меняя исходный claim.
3. `CLAIM_TYPE_AMBIGUOUS` или `CLAIM_TYPE_UNSUPPORTED` → `NARROW_CLAIM`: сузить claim до однозначного поддержанного типа. `WITHDRAW_CLAIM` допустим вместо него только после полного снятия claim и никогда не является первичным советом.
4. `SOURCE_REF_MISSING`, `BLOCKED_SOURCE`, `SOURCE_OBSERVATION_ABSENT`, `SOURCE_VALUE_MISMATCH`, `EVIDENCE_STALE`, `EVIDENCE_PRECEDES_MATERIAL_CHANGE`, `PROXY_TARGET_BRIDGE_MISSING`, `PROXY_OVERCLAIM`, `CIRCULAR_EVIDENCE`, `INDEPENDENT_VALIDATION_MISSING`, `ESSENTIAL_RELATION_NOT_EVIDENCED` → `PROVIDE_EVIDENCE`.
5. `SOURCE_SCOPE_MISMATCH`, `SOURCE_PERIOD_MISMATCH`, `SOURCE_GRAIN_MISMATCH`, `SELECTION_UNIVERSE_MISSING`, `SELECTION_RULE_MISSING`, `SCOPE_MISMATCH`, `UNSUPPORTED_GENERALIZATION`, `EVIDENCE_DATE_MISSING`, `ESSENTIAL_RELATION_MISSING` → `PROVIDE_BOUNDARY`.
6. `METHOD_UNSPECIFIED`, `METHOD_NOT_ADMISSIBLE`, `METHOD_PROFILE_INCOMPLETE`, `DISCRIMINATION_RULE_MISSING`, `DISCRIMINATION_RULE_NON_OBSERVABLE`, `RIVAL_MODEL_MISSING`, `RIVAL_PREDICTION_MISSING`, `RIVAL_TEST_MISSING`, `RIVAL_RESULT_MISSING`, `RIVAL_STATUS_MISSING`, `UNCERTAINTY_NEXT_TEST_MISSING` → `PROVIDE_METHOD`.
7. `INVALID_INPUT`, `TRACK_NOT_SUPPORTED`, `CENTRAL_CLAIM_UNRESOLVED`, `UNCERTAINTY_DECISION_MAPPING_MISSING`, `CONFLICT_DISPOSITION_MISSING` → `PROVIDE_REQUIRED_INPUT`. Для `TRACK_NOT_SUPPORTED` acceptance test возможен только на реально discovery-thread; не предлагай переименовать другой трек ради прохождения.
8. `ABSENT` или `INVALID_FORM` для `ER-01`, `ER-03`, `V-HARM-REL-01`, `REL-ESS-01`, `INF-FRESH-01`, `INF-PROXY-01`, `INF-LINEAGE-01` → `PROVIDE_EVIDENCE`; для `INF-DISC-01`, `INF-METHOD-01`, `INF-RIVAL-01`, `INF-RIVAL-02`, `INF-RIVAL-03`, `INF-UNC-02` → `PROVIDE_METHOD`; для `INF-SEL-01`, `INF-SCOPE-01` → `PROVIDE_BOUNDARY`; для остальных active CORE/closed-predicate instances → `PROVIDE_REQUIRED_INPUT`.

Для каждого action укажи `target_ids` и acceptance test того же criterion/relation instance:

- `PROVIDE_EVIDENCE`: источник содержит проверяемое наблюдение и relation переоценивается; результат может честно быть `REFUTES` или `MIXED`.
- `PROVIDE_METHOD`: указан допустимый versioned profile со всеми required fields и фактическим результатом.
- `PROVIDE_BOUNDARY`: названы наблюдаемые population/scope/period/grain либо claim сужен до них.
- `PROVIDE_REQUIRED_INPUT`: добавлен конкретный отсутствующий факт или управляющий input с цитатой и локацией.
- `ALIGN_CONCLUSION`: conclusion совпадает с вычисленным status.
- `NARROW_CLAIM`: новый scope/type однозначен и снова проверен по тем же relations.
- `WITHDRAW_CLAIM`: claim помечен снятым и исключён из active inventory.
- `LOWER_TRANSITION`: следующий commitment находится внутри границы заявленного перехода.
